# Write access stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An assistant can create a new AutomationML document from a structured description through MCP, see what it would write before it is written, and get back the same overview the read tools give for an existing document.

**Architecture:** A new tool takes a description (records, not XML), a renderer turns it into CAEX with server-generated IDs, and the write path proves the result by writing it to a temporary file, loading it with the ordinary reader and running the ordinary check before moving it into place. Writing is bounded by its own `--write` fence, separate from the read fence.

**Tech Stack:** C#, .NET 10, `System.Xml.Linq`, ModelContextProtocol 2.2.0, xUnit.

**Spec:** `docs/superpowers/specs/2026-11-09-write-access-design.md`

## Global Constraints

- The server renders CAEX itself with `XElement`; no Aml.Engine dependency is added.
- Writing is off unless `--write <dir>` is given. A read root is never a write permission.
- Output is one `.aml` file. An `.amlx` target is refused.
- Nothing half-written: render, write a temporary file, load it, check it, then move it atomically into place.
- Blocking findings are exactly the `Problems` of `Structured.Check`. `Notes` do not block and are reported.
- IDs are generated by the server from the element's path inside the document. The description cannot supply IDs. Two elements with the same name under the same parent are refused.
- The dry run works without `--write`. A real write checks the fence before it renders.
- A target the editor has open through `--follow` is refused even with the overwrite switch.
- Tool annotations: `ReadOnly = false, Destructive = true, Idempotent = true, OpenWorld = false`.
- The text half and the structured half come from one model, as in the existing tools, and `TextAndDataAgreeTests` grows a case for the new tool.
- Stage 2 seams: the renderer renders a single element as well as a whole document, and the check runs on a loaded model.
- Existing suites stay green: 188 server tests, 19 plugin tests, `python test/smoke.py examples/plant.aml`.

## Review Focus

1. A description with nothing in it at all (no libraries, no hierarchies) must be refused, not written as an empty `CAEXFile`. A description with only libraries is legitimate and must be written. Task 7.
2. Names carrying `&`, `<`, quotes or umlauts must come back unchanged through a write and a read, and the file must be UTF-8. Tasks 5 and 6.
3. A link whose endpoint names an interface that does not exist, or that is ambiguous under its element, must be refused naming the endpoint, with nothing written. Task 2.
4. A target path that is an existing directory, has no `.aml` extension, or is `.amlx` must be refused with the reason. Task 6.
5. A description large enough to make the overview enormous must still produce a bounded answer: the hierarchy class lists and the library listing keep the caps the read side already has. Task 7.
